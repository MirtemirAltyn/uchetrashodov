# ТЗ: Android-приложение учёта финансов и долгов

Nov 11, 2026 · @Алтынбек

## 1. Цель и суть

Нативное Android-приложение для личного учёта денег: доходы, расходы, переводы между счетами и долги (кто кому должен, сколько и до какого срока). Каждый расход обязательно привязан к категории, чтобы в любой момент видеть, куда уходят деньги.

Приложение работает офлайн, все данные хранятся на устройстве, один пользователь. Рабочее название: «Мои финансы».

**Как использовать это ТЗ в Claude Code:** положите текст в корень проекта как `SPEC.md`, а краткие правила (стек, архитектура, команды сборки) — в `CLAUDE.md`. Затем давайте Claude Code задачи по этапам из раздела 7, по одному этапу за раз, с проверкой сборки и тестов после каждого.

**Важно:** суммы хранить в `Long` в минимальных единицах (тыйыны/копейки), никогда не в `Double`. Балансы считать из операций, а не хранить отдельно.

## 3. Функциональные требования

### 3.1 Счета (кошельки)

- Типы: наличные, банковская карта, электронный кошелёк, накопления, другое.
- Поля: название, тип, валюта, начальный баланс, цвет/иконка, «учитывать в общем балансе», архив.
- Баланс счёта = начальный баланс + доходы − расходы ± переводы ± операции по долгам.
- Корректировка баланса: ввод фактической суммы создаёт операцию-корректировку на разницу.

### 3.2 Операции

- Типы: **Расход**, **Доход**, **Перевод** между своими счетами (с комиссией и разной валютой).
- Поля: сумма, счёт, категория (для расхода и дохода — **обязательна**), дата и время, комментарий, теги, фото чека (опционально).
- Быстрый ввод: кнопка «+» на главном экране, цифровая клавиатура с калькулятором («120+35»), сетка частых категорий. Расход записывается за 3 нажатия.
- Редактирование, удаление с отменой (Snackbar «Отменить»), копирование операции.
- Список операций сгруппирован по дням с итогом за день; поиск по комментарию; фильтры: период, счёт, категория, тип, тег, диапазон суммы.
- Регулярные операции (аренда, зарплата, подписки): периодичность (день/неделя/месяц/год), режим «создать автоматически» или «напомнить и подтвердить».

### 3.3 Категории (обязательны для всех расходов)

- Раздельные деревья для расходов и доходов; два уровня: категория → подкатегория (например, «Транспорт → Такси»).
- У категории: название, иконка, цвет, порядок, архив. Создание, переименование, перетаскивание.
- Удаление категории с операциями — только с переносом операций в другую категорию (или архивация). Операция без категории невозможна.
- Предустановленные расходы: Продукты, Кафе и рестораны, Транспорт, Авто, Жильё и коммуналка, Связь и интернет, Здоровье, Одежда, Дом, Дети, Образование, Развлечения, Подписки, Подарки, Путешествия, Комиссии, Прочее.
- Предустановленные доходы: Зарплата, Бизнес, Подработка, Подарки, Проценты, Прочее.
- По каждой категории можно открыть карточку: сумма за период, доля в %, сравнение с прошлым периодом, список операций, разбивка по подкатегориям.

### 3.4 Долги

- Два направления: **Я должен** и **Мне должны**.
- Контакты (люди/организации): имя, телефон, заметка; выбор из телефонной книги по разрешению.
- Долг: контакт, направление, сумма, валюта, дата выдачи, срок возврата (опционально), комментарий, счёт списания/зачисления, флажок «не влияет на счета» (для старых долгов).
- Частичные погашения и увеличение долга (дозайм); остаток считается автоматически; история всех движений.
- Статусы: активен, просрочен (срок прошёл), закрыт (остаток 0), списан (прощён).
- Экран долгов: итоги «Я должен / Мне должны / Сальдо», группировка по человеку (взаимные долги одного контакта сводятся в один итог), сортировка по сроку и сумме.
- Напоминания: за N дней до срока и в день срока.
- Кнопка «Напомнить»: готовый текст о долге через системный Share (WhatsApp, Telegram, SMS).
- Долги — это не доход и не расход: они меняют баланс счёта, но не попадают в отчёты по категориям.

### 3.5 Бюджеты

- Лимит на месяц на категорию или на все расходы.
- Прогресс-бар: потрачено / осталось, цвет при 80% и 100%; уведомление при превышении.

### 3.6 Отчёты и аналитика

- Периоды: день, неделя, месяц, год, произвольный; перелистывание свайпом.
- **Расходы по категориям:** кольцевая диаграмма + список категорий с суммой и % по убыванию; нажатие открывает подкатегории и операции.
- Доходы по категориям — аналогично.
- Динамика: столбцы доходов и расходов по месяцам, линия общего баланса.
- Итоги периода: доходы, расходы, разница, средний расход в день, топ-5 категорий, сравнение с прошлым периодом в %.

### 3.7 Валюты

- Основная валюта выбирается при первом запуске (по умолчанию KGS); счета и долги могут быть в USD, EUR, RUB, KZT и др.
- Курсы вводятся вручную (v1); отчёты и общий баланс пересчитываются в основную валюту.

### 3.8 Настройки и данные

- Защита входа: PIN-код и/или отпечаток; скрытие сумм на главном экране.
- Тема (системная/светлая/тёмная), язык (русский в v1, строки в `strings.xml` для будущего перевода), первый день недели/месяца.
- Экспорт операций в CSV (фильтр по периоду).
- Резервная копия: экспорт/импорт файла базы (JSON) через Storage Access Framework (сохранить в Google Drive, Telegram и т.д.).

## 4. Модель данных (Room)

Все суммы — `Long` в минимальных единицах, даты — `Long` (epoch millis), id — `Long` autoincrement. У каждой таблицы `createdAt`, `updatedAt`.

| Сущность | Ключевые поля |
| --- | --- |
| `Account` | id, name, type (CASH/CARD/EWALLET/SAVINGS/OTHER), currencyCode, initialBalance, color, icon, includeInTotal, isArchived, sortOrder |
| `Category` | id, name, kind (EXPENSE/INCOME), parentId (null = верхний уровень), icon, color, sortOrder, isArchived |
| `Transaction` | id, type (EXPENSE/INCOME/TRANSFER/ADJUSTMENT/DEBT), amount, accountId, categoryId (NOT NULL для EXPENSE/INCOME), toAccountId, toAmount (перевод в другой валюте), fee, date, note, debtId, recurringId, receiptUri |
| `Tag` / `TransactionTag` | id, name / transactionId, tagId |
| `Contact` | id, name, phone, note |
| `Debt` | id, contactId, direction (I\_OWE/OWED\_TO\_ME), principal, currencyCode, startDate, dueDate, note, status (ACTIVE/CLOSED/FORGIVEN), affectsAccounts |
| `DebtPayment` | id, debtId, kind (INITIAL/REPAY/INCREASE/FORGIVE), amount, accountId, date, transactionId |
| `Budget` | id, categoryId (null = все расходы), limitAmount, period (MONTH), currencyCode |
| `RecurringRule` | id, шаблон операции, frequency, interval, nextDate, mode (AUTO/REMIND), endDate |
| `CurrencyRate` | code, rateToBase, updatedAt |

Правила целостности:

- Остаток долга = сумма INITIAL + INCREASE − REPAY − FORGIVE; при 0 статус автоматически CLOSED.
- Платёж по долгу создаёт связанную операцию type=DEBT, если affectsAccounts = true; обе записи пишутся в одной транзакции БД.
- Отчёты по категориям учитывают только EXPENSE и INCOME (плюс комиссия перевода как расход в категории «Комиссии»).
- Индексы: Transaction(date), Transaction(accountId), Transaction(categoryId), DebtPayment(debtId).
- Схема экспортируется (`exportSchema = true`), все изменения — через миграции с тестами.

## 6. Нефункциональные требования

- **Офлайн:** всё работает без интернета, разрешение INTERNET не запрашивать.
- **Скорость:** холодный старт < 1,5 с; список из 10 000 операций листается без рывков (Paging 3); отчёт за год строится < 500 мс. Агрегаты считать SQL-запросами (SUM/GROUP BY), не в памяти.
- **Надёжность:** связанные записи — в `@Transaction`; данные не теряются при повороте экрана и убийстве процесса (SavedStateHandle).
- **Безопасность:** PIN хранится как хэш с солью; `FLAG_SECURE` при включённой защите; блокировка при возврате из фона через N минут; `allowBackup` настроен осознанно.
- **Форматы:** деньги — с пробелами между разрядами и символом валюты («12 500 сом»); даты — по локали устройства («Сегодня», «Вчера»). Расходы — красным, доходы — зелёным, но тип виден и без цвета (знак «−/+»).
- **Доступность:** contentDescription для иконок, области нажатия ≥ 48 dp, поддержка крупного шрифта.
- **Качество кода:** ktlint/detekt, unit-тесты на use cases и DAO (покрытие domain ≥ 80%), без бизнес-логики в Composable-функциях.

**Стиль**

- Шрифт Inter (или Roboto Flex), цифры табулярные. Главная сумма — 32 sp Bold, суммы в списке — 17 sp SemiBold, подписи — 13 sp.
- Скругления: карточки 20 dp, кнопки и сегменты 14 dp. Тени едва заметные (elevation 1–2), без жирных обводок.
- Отступы по сетке 8 dp, боковые поля 16 dp.
- Иконки — Material Symbols Rounded. У категорий — иконка в цветном кружке 40 dp с прозрачностью 15%. У людей — аватар с инициалами.
- Плавные анимации: смена вкладок, заполнение прогресс-баров, анимация счётчика суммы; короткая вибрация при сохранении.
- Нижняя панель: активная вкладка — иконка в светлой «пилюле» цвета основного, как в Material 3.

**Экран «Долги» (по референсу)**

1. Шапка-карточка с градиентом: крупно сальдо («−28 600 с»), под тонкой линией три колонки: «Мне должны», «Я должен», «Открытых».
2. Сегментный переключатель «Мне должны / Я должен» (+ закрытые в меню фильтра).
3. Кнопка «Записать долг» на всю ширину.
4. Чипы сортировки в одну строку с горизонтальным скроллом: «По дате», «По сумме», «По сроку», «Сначала открытые» (не переносить текст на две строки).
5. Элемент списка — отдельная карточка: аватар с инициалами • имя • комментарий · дата • сумма справа • тонкий прогресс-бар • «Возвращено 4 000 из 14 000 с» • кнопка «Вернуть часть» (для «Я должен» — «Отдать часть») • бейдж срока / «Просрочено».

## 7. Этапы разработки

Каждый этап заканчивается рабочей сборкой (`./gradlew assembleDebug`), зелёными тестами (`./gradlew test`) и отдельным коммитом. Следующий этап — только после проверки предыдущего на телефоне.

1. **Каркас.** Проект, Gradle, Hilt, тема Material 3, нижняя навигация с пустыми экранами, `CLAUDE.md`.
2. **База данных.** Все сущности, DAO, репозитории, предустановленные категории, тесты DAO и расчёта балансов.
3. **Счета и категории.** CRUD счетов, дерево категорий с подкатегориями, онбординг.
4. **Операции.** Добавление/редактирование расхода, дохода, перевода; список по дням, фильтры, поиск; Главная.
5. **Долги.** Контакты, долги, частичные погашения, сальдо по человеку, статусы, «Напомнить» через Share.
6. **Отчёты.** Расходы и доходы по категориям (кольцо + список), карточка категории, динамика по месяцам.
7. **Бюджеты и регулярные платежи.** Лимиты, WorkManager, уведомления (включая сроки долгов).
8. **Валюты, защита, данные.** Мультивалютность, PIN/биометрия, экспорт CSV, бэкап и восстановление.
9. **Полировка и релиз.** Пустые состояния, анимации, иконка приложения, R8, подписанный release APK/AAB.

Не входит в v1: облачная синхронизация, импорт банковских выписок и SMS, несколько пользователей, виджет на рабочий стол, автокурсы валют.

## 8. Критерии приёмки и стартовый промпт

- [ ] Расход записывается за 3 нажатия; без категории сохранить нельзя.
- [ ] Сумма расходов по всем категориям в отчёте равна общей сумме расходов за период (долги и переводы не входят).
- [ ] Баланс каждого счёта совпадает с ручным подсчётом после смеси доходов, расходов, переводов и погашений.
- [ ] Долг 14 000 с, погашения 4 000 + 10 000 → остаток 0, статус «Закрыт», долг уходит в закрытые.
- [ ] Сальдо в шапке долгов = «Мне должны» − «Я должен».
- [ ] Просроченные долги подсвечены, уведомление приходит в день срока.
- [ ] Бэкап → удаление приложения → восстановление даёт те же данные.
- [ ] Тёмная тема и крупный шрифт не ломают вёрстку; дизайн соответствует разделу 6.1.
- [ ] Приложение работает в режиме полёта, все тесты зелёные.
